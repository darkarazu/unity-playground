# NPC AI System - Setup Guide

This guide explains how to create and configure NPCs with AI behavior in your Unity ECS project.

## Overview

The NPC AI system reuses your existing character movement infrastructure. NPCs use the same physics, collision, and movement systems as the player, but their input is generated by AI instead of player controls.

**Supported Behaviors:**
- ✅ Patrolling within a defined area
- ✅ Following the player when in detection range
- ✅ Returning to patrol area when too far away

---

## Quick Start

### 1. Create an NPC Character

**Important:** NPCs require BOTH `CharacterAuthoring` and `NPCAuthoring` on the same GameObject!

1. **Create a new GameObject** in your scene (e.g., "NPC_Guard")
2. **Add a visual mesh** (e.g., a Capsule or your character model)
3. **Add the `CharacterAuthoring` component**
   - Set `Is Player Controlled` to **false** (unchecked)
   - Configure movement speeds (Walk Speed, Run Speed, etc.)
   - Configure `Character Properties` as needed
   - This component handles physics and movement setup
4. **Add the `NPCAuthoring` component** (on the same GameObject)
   - This component adds AI behavior
5. Unity will automatically bake the NPC entity with all required components

### 2. Configure the NPC

In the `NPCAuthoring` component, you'll see several configuration sections:

#### **Patrol Settings**
- **Patrol Center Offset**: Offset from the NPC's spawn position for patrol center (usually `0, 0, 0`)
- **Patrol Radius**: How far the NPC will roam from the patrol center (default: 10)
- **Patrol Target Reached Distance**: How close NPC needs to get to patrol point (default: 1)
- **Wait Time At Patrol Point**: Seconds to pause at each patrol point (default: 2)

#### **Follow Settings**
- **Target To Follow**: *(Optional - mainly for gizmo visualization)*
  - NPCs automatically find the player using the `PlayerTag`
  - You can assign your player GameObject here to see the cyan line in Scene view
- **Follow Detection Range**: Distance at which NPC detects and starts following (default: 15)
- **Follow Distance**: How close NPC gets to target before stopping (default: 3)
- **Max Distance From Patrol Center**: How far NPC will chase before returning (default: 25)

#### **Visualization**
- **Show Debug Gizmos**: Enable to see patrol area, detection range, and distances in Scene view

## Workflow: Hierarchy vs Subscene

You have two options for placing NPCs in your project:

### Option 1: Direct in Scene Hierarchy (Recommended for Testing)

**When to use:** Prototyping, testing, small projects
**Pros:** Simple, quick iteration, easy debugging
**Cons:** Entities baked at runtime (slight startup cost)

Simply place NPCs directly in your scene hierarchy. The `Baker` will automatically convert them to entities when you enter Play mode.

### Option 2: Subscene (Recommended for Production)

**When to use:** Large projects, many NPCs, performance-critical applications
**Pros:** Entities baked at edit-time, faster runtime, better for large worlds
**Cons:** Slightly more setup

**How to use subscenes:**
1. Create a **Subscene** in your main scene (Right-click Hierarchy → New Subscene)
2. Name it (e.g., "NPCs_Subscene")
3. Place all your NPCs inside the subscene
4. Unity will bake them at edit-time, stored as entity data

**Important:** Both approaches work with the same authoring components! Choose based on your project needs.

## Step-by-Step Example

### Creating a Patrolling Guard NPC

1. **Create the NPC GameObject**
   ```
   Hierarchy:
   └── NPC_Guard
       ├── CharacterAuthoring (Is Player Controlled = false)
       ├── NPCAuthoring
       └── Capsule (Visual)
   ```

2. **Configure `NPCAuthoring`**
   ```
   Patrol Settings:
   - Patrol Center Offset: (0, 0, 0)
   - Patrol Radius: 10
   - Patrol Target Reached Distance: 1
   - Wait Time At Patrol Point: 2

   Follow Settings:
   - Target To Follow: [Optional - for gizmo visualization only]
   - Follow Detection Range: 15
   - Follow Distance: 3
   - Max Distance From Patrol Center: 25
   ```
   
   **Note:** NPCs automatically find the player using `PlayerTag` - no need to manually assign!

3. **Play the Scene**
   - NPC will patrol randomly within a 10-unit radius
   - When player comes within 15 units, NPC will follow
   - When player moves away or NPC gets 25+ units from patrol center, NPC returns

## Setting Up the Player

**Important:** The `PlayerTag` is an ECS component, NOT Unity's GameObject Tag!

### How to Add PlayerTag to Your Player:

1. Select your **Player GameObject** in the hierarchy
2. Find the `CharacterAuthoring` component in the Inspector
3. Check the checkbox: **`Is Player Controlled` = true** ✓
4. This will automatically bake the `PlayerTag` component onto the player entity

**Common Mistake:** Don't use Unity's Tag dropdown at the top of the Inspector - that's completely separate from ECS tags!

### Verification

Your player should have:
- ✅ `CharacterAuthoring` with `Is Player Controlled` = **true**
- ✅ Player input responding (WASD movement)
- ✅ NPCs should now detect and follow when in range

## Behavior State Machine

NPCs operate in three states:

### **1. Patrolling** (Default)
- Picks random points within patrol radius
- Walks to each point
- Waits at patrol points
- **Transitions to Following:** When target enters detection range

### **2. Following**
- Sprints toward target
- Stops at `Follow Distance`
- **Transitions to Returning:** When target leaves detection range OR NPC is too far from patrol center

### **3. Returning**
- Sprints back to patrol center
- **Transitions to Patrolling:** When back inside patrol radius

## Troubleshooting

### ⚠️ Critical Setup Requirement

**NPCs MUST have BOTH components on the same GameObject:**
1. `CharacterAuthoring` (provides physics, movement, CharacterInputData)
2. `NPCAuthoring` (provides AI behavior)

Missing either component will cause the NPC to not work!

### NPC Doesn't Move
- ✅ Check that `CharacterAuthoring` has `Is Player Controlled` = **false**
- ✅ Ensure NPC has both `CharacterAuthoring` AND `NPCAuthoring`
- ✅ Verify NPC has physics components (added by `CharacterAuthoring`)
- ✅ Check Console for errors

### NPC Doesn't Follow Player
- ✅ Ensure `Target To Follow` is assigned to your Player GameObject
- ✅ Check that player is within `Follow Detection Range`
- ✅ Verify player has `CharacterAuthoring` with `Is Player Controlled` = **true**

### NPC Immediately Returns to Patrol
- ✅ Increase `Max Distance From Patrol Center`
- ✅ Check if patrol center is positioned correctly
- ✅ Ensure `Follow Detection Range` is smaller than `Max Distance From Patrol Center`

### NPC Movement Looks Jittery
- ✅ Reduce `Patrol Target Reached Distance` (try 0.5)
- ✅ Increase `Wait Time At Patrol Point`
- ✅ Check physics timestep settings in Unity

## Advanced: Multiple NPCs

You can create as many NPCs as you want! Each NPC:
- Can have different patrol areas
- Can have different behavior parameters
- Can all follow the same target (player)
- Uses the same optimized ECS systems

**Performance Tip:** The system uses Burst compilation and job scheduling, so it scales well with many NPCs.

## Advanced: Creating NPC Prefabs

1. Set up an NPC as described above
2. Drag it into your **Project** window to create a prefab
3. Instantiate the prefab in any scene
4. **Important:** Reassign `Target To Follow` in each scene (references don't persist across scenes)

## Architecture Notes (For Developers)

The NPC system demonstrates clean ECS architecture:

```
Player Flow:
CharacterInputSystem (reads keyboard/gamepad) 
  → writes to CharacterInputData 
  → CharacterMovementSystem processes movement

NPC Flow:
NPCAISystem (reads AI state, generates synthetic input)
  → writes to CharacterInputData
  → CharacterMovementSystem processes movement (SAME SYSTEM!)
```

**Key Components:**
- `PlayerTag`: Identifies player entities
- `NPCTag`: Identifies NPC entities
- `NPCPatrolData`: Patrol configuration
- `NPCTargetData`: Follow/chase configuration
- `NPCStateData`: Current AI state (Patrolling/Following/Returning)
- `CharacterInputData`: **Shared** between player and NPCs!
